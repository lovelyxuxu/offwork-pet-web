## 后续维护

查看服务：

```sh
sudo systemctl status offwork-pet-web
sudo journalctl -u offwork-pet-web -n 50 --no-pager
sudo nginx -t
```

更新角色和软件展示信息：

```sh
cd /srv/offwork-pet-web/current
sudo -u offwork-web .venv/bin/python -m portal.manage --data-dir /var/lib/offwork-pet-web import-pack /path/to/character.petpack
sudo -u offwork-web .venv/bin/python -m portal.manage --data-dir /var/lib/offwork-pet-web import-release /var/www/offwork-pet-updates/latest.json
```

正式发布新角色前仍需使用桌宠项目的完整规则校验器。发布软件后重新导入更新清单，网站版本信息才会同步。角色下载后的客户端导入方式不变，暂未接入客户端内在线浏览和一键安装。

后续源码部署使用 `tools/deploy.py`，先提交工作区，再按同级项目 `docs/server-access.md` 读取加密 SSH 凭据，通过标准输入传入密码。不要向服务器上传 GitHub 或软件发布私钥。

如需恢复本次部署前的网站入口，应先检查备份内容，恢复 `nginx.tar.gz` 并运行 `nginx -t` 后重载。最早备份对应原旧站入口，本次备份还包含新网站已有内容的一致 SQLite 快照及内容归档；根据实际恢复目标选用。恢复网站代码时切换 `current` 链接并重启网站服务；搭子服务保持独立。

部署工具已处理当前 Ubuntu 缺少 ensurepip 的环境：用 `venv --without-pip` 创建隔离环境，再由已有 pip 的 `--python` 选项向目标环境安装。Nginx 重载后会等待新路由健康响应，避免旧工作进程短暂返回旧上游 502 时误判。
